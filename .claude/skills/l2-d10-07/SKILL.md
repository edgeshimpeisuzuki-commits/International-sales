## D10-07 クライアントの更新・解約(Account Agent)― P1は更新の準備だけ(定義書 22.8 前倒しした2件の定義(11/14))

| 項目 | 内容 |
| --- | --- |
| 入力 | Contract(期間・更新日・報酬条件)、月次レポート(D13-07)、報酬の実績(D13-05)、KPI(D13-17)、クライアントからの問合せ・要望(D10-10) |
| 出力 | 総括レポート(契約期間の成果・課題・次の期間の計画)、条件の見直し案(報酬率・対象国・商品・期間)、更新の打合せの候補日 |
| 手順 | 1. 契約の更新日をD12-11に登録する 2. 更新の30日前に、契約期間の実績を集計する 3. 総括レポートと条件の見直し案を作る(自社の収支も並べる) 4. 人が方針を決める(更新 / 条件を変えて更新 / 終了) 5. 承認されたレポートをクライアントに送り、打合せを調整する 6. 合意したらD13-01(契約)とD02-09(クライアント設定の変更)に渡す |
| 判断の基準 | 見直し案には「なぜ変えるか」を実績の数字で示す。自動更新の契約でも、更新日の30日前に必ず準備を始める。解約の申し出期限が契約にあれば、その期限の30日前を開始日にする |
| 自律度 | L2(集計と資料づくりだけ。方針と契約は人) |
| 人に回す条件 | 方針の決定のすべて / クライアントから解約・条件変更の申し出があった |
| 禁止事項 | 更新・解約・条件をクライアントに約束しない / 承認前のレポートを送らない |
| ツールと権限 | 契約・レポート・報酬の読み取り、資料の作成。クライアントへの送付は承認後 |
| 品質の評価 | 更新日の30日前に総括レポートができていた割合(目標100%) |
| 失敗時の処理 | 準備が間に合わない→人に知らせ、契約の更新の扱い(自動更新に任せるか)を人が決める |

補足(11/16テスト):クライアントからの連絡の受付と回答は、D10-10(l2-d10-10)の手順に従う。
