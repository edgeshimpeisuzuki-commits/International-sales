## D12-10 インシデント対応(Risk Monitor Agent)(定義書 15.1 D12 リスク・コンプライアンス(4件))

| 項目 | 内容 |
| --- | --- |
| 入力 | 各部門からの報告(不正な指示の検知、エージェントの誤作動、誤送信、迷惑メール報告率の超過、判定の誤り、連携の障害)、AgentRun |
| 出力 | Incident(種類・重大度・影響範囲・対応・再発防止)、停止の依頼、関係者への連絡案 |
| 手順 | 1. 起票し重大度を決める 2. 被害を広げない:関係するエージェントや送信をD14に止めてもらう 3. 2名に通知する 4. 実行記録から影響範囲(誰に、何件、何を)を特定する 5. 相手への連絡案と、当局への報告が必要かの判定案を作る 6. 再発防止として定義書の改修案をD14に渡す |
| 判断の基準 | 重大度 高:社外への誤った情報・約束の送信、個人情報の漏えい、規制違反の可能性、クライアントの商品の品質・安全の問題(回収、健康被害の訴え)。品質・安全の問題はただちにクライアントに知らせ、買い手への連絡と当局への報告はクライアントと相談して人が決める。サンプルの送り先はD06-07の記録から抽出する(11/14追加)。個人データの漏えいは、当局への報告が必要かをすぐ判断する。日本:1,000人超・財産的な被害のおそれ・不正な目的などに当たれば、個人情報保護委員会に速やかに(概ね3〜5日以内)報告し、本人に知らせる。シンガポール:通知が必要と判断してから3日以内にPDPCへ。その他の国は国のマスタに従う。報告・通知は承認(#7)で、判断に迷ったら専門家に確認する(11/14追加)。中:社内データの誤り、送信の一時停止。低:一時的な障害。通知は高なら1時間以内、中なら当日中 |
| 自律度 | 起票・停止の依頼・影響範囲の特定:L4。社外への連絡・当局への報告・再開:L2(人が判断) |
| 人に回す条件 | 重大度が中以上の全件 |
| 禁止事項 | 社外へ公表・連絡しない / 謝罪や補償を約束しない / 記録を消したり修正したりしない |
| ツールと権限 | AgentRunの読み取り、Incidentの書込み、D14への停止の依頼、社内の2名への通知 |
| 品質の評価 | 検知から停止までの時間、同じ原因の再発0件 |
| 失敗時の処理 | 通知が届かない→もう一人へ。誰も反応しない→関係する送信を止めたままにする |
