## D14-18 業務定義の維持(Program Orchestrator)(定義書 21.6 反映した内容(11/13))

| 項目 | 内容 |
| --- | --- |
| 入力 | 未分類の業務の記録(AgentRun・ActivityでL2が空のもの、人が手でやった作業のメモ)、定義書、L2業務シート、各部門の改善提案(D14-05) |
| 出力 | 週次の見直し資料、定義書の改訂、L2の追加・変更・廃止、変更履歴(日付・内容・理由・承認者) |
| 手順 | 1. L2が空の実行と、人の手作業のメモを週次で集める 2. 既存のL2に入るものと、新しいL2が必要なものに分ける 3. 新しいL2は11項目の案を作る 4. 週次の見直しで人が決める 5. 定義書とシートを同じ日に直し、変更履歴に残す 6. 影響するエージェントの指示文の更新をD14-10に依頼する |
| 判断の基準 | 同じ未分類の業務が4週で2回以上、または社外に影響するものは1回でもL2化を検討。定義書が正本で、シートと食い違うときは定義書に合わせる。定義書の1つのタブには大きさの上限(20,000ブロック)があるため、上限の80%を超えたら、検査記録など読み返す頻度の低い章から別のタブに移す。定義そのものを移すときは、元の場所に移した先を書く(11/14追加) |
| 自律度 | L2(案まで。改訂の確定は人) |
| 人に回す条件 | すべての改訂 / 承認ゲート・自律度・禁止事項の変更(19.5の権限移譲の対象外) |
| 禁止事項 | 承認なく定義書・シートを書き換えない / 履歴を残さずに変えない |
| ツールと権限 | AgentRun・Activityの読み取り、定義書・シートの読み取りと改訂案の作成(反映は承認後) |
| 品質の評価 | 未分類の業務の件数(減っていくこと)、定義書とシートの食い違い(目標0) |
| 失敗時の処理 | 食い違いが判明→定義書に合わせて直し、どの改訂でずれたかを履歴に残す |
