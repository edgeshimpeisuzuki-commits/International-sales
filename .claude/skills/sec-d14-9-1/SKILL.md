## 9.1 マスタ・データ品質(Data Steward Agent)

| 項目 | 内容 |
| --- | --- |
| 担当L2 | D14-01 マスタの管理・名寄せ(P1)、D14-02 データ品質の監視(P1)、D14-12 Market・Channelマスタ(P1)、D14-09 データの保持・廃棄(P2) |
| 入力 | Party・Contactの候補、全エンティティ、Policy(データ保持)、国・チャネルの公開情報 |
| 出力 | 正本のParty(ID付与・統合)、品質アラート、Market・Channel、保持・廃棄の記録 |
| 手順 | 名寄せ:1. 候補を受け取る 2. 登録番号→ドメイン→正規化した社名＋国の順に照合 3. 判定(既存 / 新規 / 要確認)を返す 4. 要確認は承認に回す。品質:毎朝、下のルールで全件を検査し、オーナー部門にアラートを出す。保持:月次に期限切れを抽出し、廃棄を承認に回す |
| 判断の基準 | 自動統合:登録番号かドメインが一致。要確認:社名だけが似ている、グループ会社の可能性。品質ルール:必須項目の欠損、形式(メール、国コードはISO形式)、重複、参照先の欠落(例:DealのPartyがない)、鮮度(取得から90日を超えたContactは再確認(標準パラメータ、11/14変更)) |
| 自律度 | L4(名寄せの判定、品質監視、マスタの更新)。要確認の統合と廃棄は承認 |
| 人に回す条件 | 要確認の統合 / 品質アラートが同じ部門で3日続く / 統合すると紹介顧客の登録が重なる |
| 禁止事項 | 統合で元のデータを消さない(統合前のIDと履歴を残す) / オーナーでないエンティティの中身を書き換えない / 配信停止の記録を廃棄しない(再送信を防ぐため) |
| ツールと権限 | 全エンティティの読み取り。書込みはParty・Market・Channelと品質アラートのみ。外部への送信権限なし |
| 品質の評価 | 重複率・欠損率(8.7)。自動統合を月に20件抽き取り、誤統合ゼロを確認 |
| 失敗時の処理 | 照合できない→「要確認」として返し、登録は止めない / 誤統合が判明→履歴から元に戻し、影響した部門に通知 |
