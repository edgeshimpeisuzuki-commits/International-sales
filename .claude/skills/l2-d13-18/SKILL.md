## D13-18 自社の料金体系の設計(Program Orchestrator)(定義書 20.3 経営管理・統制(5件))

| 項目 | 内容 |
| --- | --- |
| 入力 | Engagement(収支、D16-05。D16-05はP2なので、P1は案件ごとの工数とAIコストの記録を使う)、各クライアントの契約条件、AI利用コスト(D14-11)、競合の公開料金(輸出支援・営業代行) |
| 出力 | Policy(料金表:成果報酬率・固定報酬・最低額・実費の扱い・値引きの範囲)、料金ごとの採算試算 |
| 手順 | 1. クライアント・案件ごとの収支(時間・AIコスト・実費)を集計する 2. 競合の公開料金を集める 3. 料金モデルごとに、取引額の大小で採算を試算する 4. 料金表の案を出し、人が決める 5. 決まった料金表をD02-08・D16-01の提案で使う |
| 判断の基準 | 案件ごとに赤字にならないこと(AIコストと実費を含む)。既存クライアントの条件は契約期間中は変えない |
| 自律度 | L2(案まで。決定は人) |
| 人に回す条件 | すべての決定・変更 / 料金表外の個別条件 |
| 禁止事項 | 競合の非公開情報を使わない / あるクライアントの条件を別のクライアントに開示しない |
| ツールと権限 | Web検索、収支・契約の読み取り、料金表の案の作成 |
| 品質の評価 | 赤字の案件の数(目標0)、提案で料金を理由に断られた割合 |
| 失敗時の処理 | 赤字の案件が出た→原因(工数・コスト・料率)を分けて、次の料金表の見直しに渡す |
