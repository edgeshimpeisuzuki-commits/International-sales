## 商談資料の標準セット

| 資料 | 内容 | 形式 | 相手に出すか |
| --- | --- | --- | --- |
| 会社紹介(1枚) | 代行の立場、クライアントの会社概要と産地、主な商品 | PDF・英語 | 出す |
| 提案書のひな形(10枚前後) | ①私たちについて ②クライアントと産地 ③用途別の商品構成 ④品質・規格・認証 ⑤取引条件 ⑥物流 ⑦サンプルから初回取引までの流れ ⑧相手向けの提案(D06-20で毎回作る) | スライド・英語 | 出す |
| 商品カタログ | 商品ごとの規格・荷姿・MOQ・保存条件・賞味期限 | PDF・英語 | 出す |
| 規格書・認証書の写し | 保有書類(D06-12と同じフォルダ)の有効な版 | PDF | 求められたら出す |
| 想定Q&A | よくある質問と回答、失注理由への答え方(KnowledgeArticleから) | 社内用 | 出さない |

## D05-10 商談資料の標準セットの作成・更新(D05 Content Agent)

| 項目 | 内容 |
| --- | --- |
| 入力 | Product、PriceList、Certification、ProductCompliance、ブランド・ポジショニング(D05-01。P2で定義するまでは、クライアントから入手した会社案内と資料で代える)、KnowledgeArticle(よくある質問・失注理由)、クライアントから入手した資料 |
| 出力 | 標準セット(上の表)、版と更新日 |
| 手順 | 1. クライアントの立ち上げ時に作る 2. 表現をD04-07に通す 3. 会社・産地・品質の頁はクライアントに事実確認を依頼する 4. 承認後に版を付けて公開する 5. 更新のきっかけが来たら差分だけ直し、承認に回す |
| 判断の基準 | 事実は元データ(マスタ)からだけ取る。更新のきっかけ:価格改定、新商品、認証の取得・失効、適合判定の変更、よく出る質問の追加(月次) |
| 自律度 | L3(初版と改訂は承認(#89。1名)、3日以内。日付や誤字だけの更新はL4) |
| 人に回す条件 | クライアントの事実確認で修正が出た / 認証の失効 |
| 禁止事項 | 失効した認証を載せたままにしない / 承認前の版をD06-20に使わせない |
| ツールと権限 | マスタの読み取り、資料の生成。書込みはContent(標準セット) |
| 品質の評価 | 元データとの不一致ゼロ / 古い版の利用ゼロ |
| 失敗時の処理 | 元データが変わったのに改訂が未承認→旧版に「改訂中」と付け、変わった頁はD06-20で使わない |
