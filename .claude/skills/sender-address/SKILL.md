定義書 D14-17。監視と停止はL4。送信の再開・上限の引き上げ・設定の変更は人の承認。

## 送信開始前(1回)
1. クライアント設定の送信用アドレス(config/clients/<client>.yaml の address_env)以外から送らない。
2. そのドメインの SPF・DKIM・DMARC が設定済みかを確かめる(DNSの公開情報で確認。設定はクライアント側、確認担当は渡辺さん)。未設定なら送らない。
3. 送信先の国の営業メールの法律を国のマスタで確かめる(SGは `<ADV>`・配信停止・30日以上有効な連絡先)。
4. Postmaster Tools などの数字は、クライアントに登録と月1回の共有を依頼する。

## 1日の上限(毎朝)
- 上限は config/clients/<client>.yaml の daily_send_cap。慣らしは warmup_start から始め、直前の期間が基準内のときだけ段階的に上げる(上げるのは承認)。
- 1アドレスで複数の国に送るときは、国ごとの目標社数の比で上限を分ける。
- 上限に達するときの順:①相手への返信 ②予定日のフォロー ③再接触の提案 ④新規の初回。

## 監視(毎朝)と停止
- 台帳の送信実績から、不達・苦情・「迷惑」の返信を数える。基準は config/standard-params.yaml の stop_rules(苦情1件で半分、1週間に2件で全停止、不達率2%で停止)。
- 当たったら新規の送信を止め、2名に知らせ、D12-10へ。返信は続ける。
- 数字が取れない日は上限を上げず、人に知らせる。

## 禁止
- 上限を超えて送る、認証が未設定のまま送る、停止中に別のアドレスで新規の送信を続ける。
