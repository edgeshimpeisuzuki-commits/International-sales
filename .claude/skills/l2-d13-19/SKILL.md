## D13-19 承認権限の規程(人 ＋ Program Orchestrator)(定義書 15.2 D13 コーポレート(4件))

| 項目 | 内容 |
| --- | --- |
| 入力 | 各部門の承認ゲート(4.6・8.6・11.5、本章)、Actor、Budget |
| 出力 | Policy(承認権限:操作×承認者の数×金額の上限×代理の可否)。初版の案は15.3 |
| 手順 | 1. 各部門の承認ゲートを集めて一つの表にする 2. 重複・矛盾を直す 3. 1名(鈴木か渡辺)が決める 4. D14-03がその表どおりに承認を回す 5. 部門を足すたびと年次に見直す |
| 判断の基準 | 取り消せないもの・お金や法的な義務が生じるもの、社外への発信は承認(1名)、社内で完結し戻せるものは事後報告。承認の人数はすべて1名(鈴木か渡辺。本人の承認も可。11/16決定) |
| 自律度 | L2(決めるのは人。エージェントは集約と矛盾の検出まで) |
| 人に回す条件 | 全件 |
| 禁止事項 | エージェントが規程を変えない / 承認者の数を減らす変更を自動で反映しない |
| ツールと権限 | 定義書の読み取り、Policyの下書き |
| 品質の評価 | 規程にない承認依頼の数(少ないほどよい)、部門の定義書との食い違い0件 |
| 失敗時の処理 | 規程にない操作の承認依頼が来た→暫定で承認(1名)が要るものとし、規程の追加を提案する |
