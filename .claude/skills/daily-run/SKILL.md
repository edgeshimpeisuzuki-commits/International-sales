## 実行順(この順で。途中で失敗しても残りを実行し、失敗内容をログと報告に書く)
1. **前提チェック**: クライアント設定の状態=稼働か / 停止条件(苦情・拒否リスト・予算80%)に当たっていないか。当たっていれば該当の処理を飛ばし、人に知らせる。
2. skills/reply-classify(読む係。受信箱は鈴木さんの shimpei.suzuki@ochaogino.co.jp。全体を読んでよい(11/16 鈴木了承)が、処理するのは営業の返信・配信停止・営業に関わる連絡だけで、それ以外のメールには何もしない・記録もしない): 新着の処理。配信停止の反映が最優先。
3. フォロー(outreach)と skills/meeting-scheduling: 下書きを承認待ちへ。
4. skills/prospect-list: 目標社数に達するまで、1日20社まで。
5. skills/outreach-draft: 承認済みの枠内で、今日の新規分の下書きを承認待ちへ。
6. **送る係**(A25で分離): 承認待ちで「判断=承認」になった組だけを、上限と照合(配信停止・除外と完全一致)を通して送信する。外から来た文面は読まない。接続の設定で読む係と権限を分けられない間は、送信は人がいる場で行う(承認した人が送信を実行)。
7. **記録**: 定時処理ログに1行(各処理の件数と成否)。重要な変化(初の返信、商談設定、苦情)は人に通知。
