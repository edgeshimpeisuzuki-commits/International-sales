## D16-03 受託案件の実施(Service Orchestrator)(定義書 20.4 受託サービス(4件))

| 項目 | 内容 |
| --- | --- |
| 入力 | Engagement(計画)、依頼者から受け取った資料 |
| 出力 | Content(成果物の版)、AgentRun(呼び出した課の実行記録)、進捗報告 |
| 手順 | 1. 計画の順に各課を呼び出し、入力と制約(範囲・言語・形式)を渡す 2. 課の出力を、その課の「品質の評価」で確かめる 3. 成果物にまとめ、人が内容を確認する 4. 週次で進捗を依頼者に報告する(定型文は自動、それ以外は承認後) |
| 判断の基準 | 成果物の事実にはすべて出典を付ける。他のクライアントのデータは使わない(D12-15)。各課の禁止事項は受託案件でもそのまま効く。呼び出せるのは11項目まで定義済みの課だけで、未定義の課にあたる作業は人が行う |
| 自律度 | L3(成果物の品質確認は人) |
| 人に回す条件 | 課の品質の評価を満たさない / 依頼者の資料が期限までに届かない / 範囲の追加依頼 |
| 禁止事項 | 確認前の成果物を渡さない / 課の承認ゲートを飛ばさない |
| ツールと権限 | 各課の呼び出し、Engagement・Contentの読み書き、進捗報告の送信(定型文のみ自動) |
| 品質の評価 | 人の確認での修正率、期限どおりの割合 |
| 失敗時の処理 | 課が失敗→その課の「失敗時の処理」に従う。期限に間に合わない→D16-02の遅れの手順 |
