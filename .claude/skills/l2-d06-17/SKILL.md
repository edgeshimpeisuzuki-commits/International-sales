## D06-17 案件ごとのクライアントへの条件確認(Deal Agent)(定義書 5.5 P1で動く追加分の定義(D06-12・16・17・18))

| 項目 | 内容 |
| --- | --- |
| 入力 | Deal(希望商品・数量・国・納期・荷姿)、PriceList(クライアント設定で指定した価格表)、SupplierCapacity、ProductCompliance、Contract |
| 出力 | 確認依頼(Activity)、Deal(条件確認済み:供給可否・MOQ・単価・リードタイム・回答日) |
| 手順 | 1. 買い手の要求を項目に整理する 2. 価格表・MOQ・適合判定で回答できる範囲かを判定する 3. 範囲内なら「確認不要」と記録する 4. 範囲外なら確認依頼文案を承認に回す 5. 回答をDealに記録し、3日無回答なら催促案を作る |
| 判断の基準 | 確認が必要:個別価格 / MOQ未満 / 1回あたりクライアント設定の「確認が必要な数量」を超える / 価格表にない商品 / 特別な包装・OEM / 納期の指定 / 支払条件・独占・代理店や販売店の契約の要求(11/14追加)。それ以外は確認不要 |
| 自律度 | L3(確認の要否の判定はL4) |
| 人に回す条件 | クライアントが供給不可と回答 / 5日無回答 / ブランド・OEMの要求 |
| 禁止事項 | クライアントの回答前に、買い手へ供給の可否を伝えない / クライアントの仕入値・内部の原価を買い手に開示しない |
| ツールと権限 | 価格表・Dealの読み取り、ActivityとDealの書込み、承認後の依頼の送付 |
| 品質の評価 | 回答までの日数 / 確認後に条件が変わった割合 / 「確認不要」と判定して後で問題になった件数(ゼロが目標) |
| 失敗時の処理 | 価格表の改定日が90日より前→全件を「確認が必要」として扱い、D03に知らせる |
