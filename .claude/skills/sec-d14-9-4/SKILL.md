## 9.4 ナレッジ・AI方針(AIOps Agent ＋ Data Steward Agent)

| 項目 | 内容 |
| --- | --- |
| 担当L2 | D14-13 AIガバナンス(P1)、D14-14 ナレッジの蓄積・更新(P1) |
| 入力 | AgentRun、Activity、Deal(失注理由)、Ticket、承認時の修正内容、AIサービスの利用規約 |
| 出力 | KnowledgeArticle(種類・根拠・確認日・有効期限)、Policy(AI方針) |
| 手順 | ナレッジ:1. 週次に素材を集める(返信率の高い文面、失注のパターン、規制判断の事例、よくある質問) 2. 下書きを作る 3. 公開を承認に回す 4. 180日ごとに再確認する。AI方針:年次と新しいモデル・サービスの導入時に案を作る |
| 判断の基準 | ナレッジにするのは、根拠(実績の数字か出典)があるものだけ。AI方針に必ず含めるもの:使うモデルとサービス、AIに入れてよいデータの範囲(クライアントの原価など)、生成物の責任(送った文面は送信者の責任)、AI作成の開示の方針 |
| 自律度 | ナレッジの下書き:L4、公開:L3。AI方針:L2 |
| 人に回す条件 | 既存ナレッジと矛盾する / 例が1件しかない |
| 禁止事項 | 根拠のない一般論をナレッジにしない / 個人情報やクライアントの機密をナレッジ本文に入れない / 別のクライアントの機密を混ぜない(2社目以降) |
| ツールと権限 | 各記録の読み取り、KnowledgeArticleの下書き。公開は承認後 |
| 品質の評価 | ナレッジを使った業務の修正率、期限切れナレッジの件数 |
| 失敗時の処理 | 誤ったナレッジが判明→非公開にし、それを使った実行を記録から抽出して影響を確認 |
