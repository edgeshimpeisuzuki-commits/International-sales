## 9.2 承認・権限(Program Orchestrator ＋ 人)

| 項目 | 内容 |
| --- | --- |
| 担当L2 | D14-03 承認ワークフローの管理(P1)、D14-06 権限・セキュリティの管理(P1はログイン情報・安全基準・クライアントごとのデータの分離のみ、その他はP2) |
| 入力 | 各部門からの承認の依頼、Policy(承認権限、D13)、Actor |
| 出力 | ApprovalRequest(結果・修正内容・承認者・時刻)、通知、Actor(権限) |
| 手順 | 1. 依頼を受け取り、承認が要るかを規程から決める(承認者は1名。鈴木か渡辺。11/16決定) 2. 「何を・なぜ・どうなるか」を3行で要約して通知する 3. 結果を記録し、承認IDを依頼元に返す 4. 期限の2時間前に催促する 5. 期限切れは「未承認」として実行させず、翌朝の一覧に載せる |
| 判断の基準 | 結果は3種(承認 / 修正して承認 / 却下)。修正して承認した場合は、修正の種類(事実の誤り / 表現 / 方針の違い)を記録し、評価(9.3)に使う。似た依頼はまとめて一括承認できる形で出す |
| 自律度 | 承認の仲介:L4。権限の設定:L2(人が行う) |
| 人に回す条件 | 規程にない種類の操作 / 承認のあと、実行前にもう1名が異議を出した(実行を止めて人に回す。内容を直して出し直す) |
| 禁止事項 | エージェントが承認しない(代理承認も不可) / 承認IDのない固定ゲートの操作を通さない / 承認後に内容を変えない(変えるなら再承認) |
| ツールと権限 | 通知の送信(社内の2名のみ)、ApprovalRequestの書込み。権限の変更は人だけ |
| 品質の評価 | 承認の待ち時間、期限切れの件数、承認なし実行0件 |
| 失敗時の処理 | 通知が届かない→もう一人に通知 / 記録に失敗→その承認は無効として依頼元は実行しない |
