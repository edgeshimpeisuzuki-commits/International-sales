定義書「部門定義書(第2波以降)」タブのD06追補をそのまま写したもの。正本は定義書(D14-18)。共通の決まりは docs/common-rules.md。

## 流れ(D06-05・D06-20・D05-10)
1. Dealが「商談設定」になる → 相手企業の事前調査(D06-05、L4)
2. 商談計画を作る(D06-05):目的・議題・未確認のヒアリング項目・想定Q&A・提示してよい条件の幅。価格表の範囲を超える条件が要りそうなら、D06-17でクライアントに事前確認する
3. 標準セット(D05-10)から相手向けの提案書を作る(D06-20)。表現はD04-07を通し、数値は元データと突合する
4. 商談の48時間前までに、商談計画と提案書をまとめて承認に回す → 人が24時間前までに確認する(#88。当面2名、商談ごと)
5. 人が商談を行う → 議事録・次アクション(D06-11)

## D06-20 提案書の作成(Deal Agent ＋ 資料作成ユーティリティ)

| 項目 | 内容 |
| --- | --- |
| 入力 | 商談計画(D06-05)、標準セット(D05-10)、Product、PriceList、Certification、ProductCompliance、KnowledgeArticle |
| 出力 | Content(相手向けの提案書。英語のスライドとPDF)、添付一式(会社紹介・カタログ・必要な規格書と認証書)、事前送付の要否と送付文案 |
| 手順 | 1. 標準セットの承認済みの最新版を使う 2. ⑧相手向けの提案(用途の提案・推奨商品・使い方の例・サンプルの案内)を作る 3. 推奨商品の規格・認証・取引条件の頁を相手の国の条件に合わせる 4. 表現をD04-07(広告・表示の法令チェック)に通す 5. 価格・規格・単位の換算を元データと突合する 6. 商談の48時間前までに、商談計画と合わせて承認に回す 7. 承認後、事前送付が必要なら送り、使った版を記録する |
| 判断の基準 | 10枚前後。相手の業態に合う用途を1つ以上入れる。価格を載せるのは2回目以降の商談か、相手が求めたときで、通貨・インコタームズ・有効期限・MOQ・単位を明記する。初回は価格帯のみ。相手の言語が英語以外でも提案書は英語(訳は別にL3) |
| 自律度 | L3(商談の前に人が確認) |
| 人に回す条件 | 標準セットにない主張(新しい用途・効能・実績)を入れたい / 価格表外の価格 / 相手が独自の書式や提出物を指定した |
| 禁止事項 | 未取得の認証を「取得済み」と書かない / 効能・健康効果をD04-07を通さずに書かない / 他の買い手やクライアントの名前・取引条件を載せない / クライアントの仕入値・原価を載せない / 承認前に相手へ送らない |
| ツールと権限 | 標準セットと保有書類の読み取り、スライドとPDFの生成。書込みはContent(提案書)。送付は承認後のみ |
| 品質の評価 | 承認時の修正率(2か月目に20%未満)/ 数値の不一致ゼロ / 商談から見積・サンプルに進んだ割合 |
| 失敗時の処理 | 突合で数値が合わない→承認に回さず作り直す / D04-07で不可→その表現を外して作り直し、外した内容を人に知らせる |

未決:提案書の名義(クライアントの名前で出すか、代行として自社名も入れるか)とデザイン(クライアント設定#29、確認事項の12。最初の商談の前)。
