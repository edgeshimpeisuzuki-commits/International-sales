## D13-09 資金調達(融資・助成金・投資家)(Finance Agent)(定義書 20.3 経営管理・統制(5件))

| 項目 | 内容 |
| --- | --- |
| 入力 | 事業計画・Budget・資金繰り表(D13-08)、制度の一覧(D01-07から、公的な融資・助成金・自治体の創業支援)、各制度の募集要項 |
| 出力 | Filing(申請書の下書き・提出記録)、申請の工程表(締切・必要書類・面談日)、採択後の報告義務の期限 |
| 手順 | 1. 資金繰り表から必要額と時期を出す 2. 使える制度を要件・金額・締切で並べる 3. 人が申請先を決める 4. 募集要項に沿って申請書を下書きする(数字は事業計画と会計の記録から) 5. 必要書類のそろいを確かめる 6. 提出・面談は人 7. 採択後の報告期限をD12-11に登録する |
| 判断の基準 | 申請書の数字は事業計画・会計の記録と一致させる。将来の売上は「計画」と明記し、前提(クライアント数・取引数)を書く。補助金は、交付決定の前に発注・契約・支払いをしない。対象の経費は他と分けて記録し、証憑をそろえる。採択後の報告(実績報告・事業化の状況の報告など)と、補助金で買ったものを処分できない期間をD12-11に登録する(11/14追加) |
| 自律度 | L2(下書きと工程管理まで。申請・契約は承認) |
| 人に回す条件 | すべての提出・契約 / 個人保証・担保がある場合 / 投資家との条件 |
| 禁止事項 | 実績を盛らない / 事実と異なる申告をしない / AIが申請系システムにログインして提出しない |
| ツールと権限 | Web検索、事業計画・会計の読み取り、申請書の作成 |
| 品質の評価 | 書類の不備による差戻し(目標0)、採択率 |
| 失敗時の処理 | 不採択→理由を記録し、次の制度に活かす。締切に間に合わない→次の募集回を登録 |
