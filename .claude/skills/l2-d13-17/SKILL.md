## D13-17 KPI体系の設計(Program Orchestrator)(定義書 20.3 経営管理・統制(5件))

| 項目 | 内容 |
| --- | --- |
| 入力 | 各部門定義書のKPI(4.7・8.7・11.6など)、Program、Budget、クライアントと合意した報告項目 |
| 出力 | Policy(KPI定義:名前・計算式・データの出どころ・更新の頻度・目標値・責任部門) |
| 手順 | 1. 各部門のKPIを集め、同じものを名寄せする 2. 「売上(取引額)←受注←商談←返信←送信」のようにつながりを図にする 3. 計算式とデータの出どころを一つに決める 4. 目標値の案を出し、人が決める 5. クライアント向け報告(D13-07)に使う項目を指定する |
| 判断の基準 | KPIは「データが自動で取れるもの」だけ。部門をまたぐ同名のKPIは計算式を一つにする。P1の目標は「仮」とし、実績4週分で見直す |
| 自律度 | L2(案まで。決定は人) |
| 人に回す条件 | 目標値の決定 / 定義の変更(過去の数字と比較できなくなるため) |
| 禁止事項 | 定義を黙って変えない(変えるときは変更日と旧定義を残す) |
| ツールと権限 | 定義書・実績データの読み取り、Policy(KPI定義)の案の作成 |
| 品質の評価 | 全KPIのうち自動で集計できる割合(目標100%)、部門間で数字が食い違う件数(目標0) |
| 失敗時の処理 | 数字の食い違い→定義の差を特定し、どちらに合わせるか人が決める |
