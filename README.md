# knock-knock-agents

日本のメーカーの海外営業を代行するAIエージェント一式です。
業務の正本は「部門定義書(要件定義)」と「業務ブループリント」で、このリポジトリはそれを動かすための設計図(指示文・手順・設定・ツール)を置きます。

## 置き場の分担

| 層 | 置き場所 | このリポジトリに置くか |
|---|---|---|
| 定義(指示文・手順・設定) | このリポジトリ | 置く |
| 実行 | P1:Claude Codeの定期実行 / P2:サーバー(Agent SDK)か Managed Agents | 置かない(設定だけ置く) |
| データ(案件・連絡先・承認記録・ログ) | P1:スプレッドシート / P2:データベース | **置かない** |
| 鍵(APIキー・メールの接続情報) | GitHub Secrets・クラウドの鍵管理 | **置かない**(`.env.example` に名前だけ) |
| 頭脳 | AnthropicのAPI(組織アカウント1つ) | 置かない |

## フォルダ

```
.claude/agents/   部門(オーケストレーター)と課(ドメインエージェント)の指示文
.claude/skills/   繰り返し使う手順(リスト作成・文面作成・返信分類・商談準備など)
config/           標準パラメータとクライアント設定
docs/             正本へのリンク、決定の記録
tools/            外部サービスとつなぐツール(P2から)
data/             ローカルの作業用(Gitに上げない)
```

## 2人で使うときの決めごと

1. 変更はブランチを切り、プルリクエストでもう1人が確認してから `main` に入れる。
2. 定期実行は1か所(P1はClaude Codeの定期実行、P2はサーバー)だけで動かす。各自のPCでは動かさない(二重送信を防ぐ)。
3. 社外への送信・提示は、必ず承認の受信箱を通す(定義書 4.6)。
4. 買い手の連絡先や個人情報はリポジトリに入れない。
5. 定義書・シートと食い違う変更は、先に定義書を直してから入れる(D14-18)。
